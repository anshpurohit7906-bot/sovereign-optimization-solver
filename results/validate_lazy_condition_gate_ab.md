## Trajectory equivalence (per-iteration checks)

For every recorded iteration/simplex event, CURRENT and LAZY were compared on:

- objective (within 1e-9)
- basis hash (identical basis list)
- gate decision (no_action / soft_clamp / repair)
- min_xB (within 1e-9)
- neg_basic_count (identical)
- reduced-cost summary: min (rc_min), negative-count (rc_neg), sum (rc_sum)
- aggregate repair count and soft-clamp count (identical at every step)
- effective tolerance staleness: `stale_eff_iters` counts iterations where
  the effective tolerance value differs between modes (LAZY reuses the last
  computed value when the condition is skipped).

**Trace granularity caveat**: on the long PILOT87 run the per-iteration trace
persists event records only at exit/return points (objective, basis hash, gate,
min_xB, neg count, rc summary are snapshotted at each exit and compared between
the modes). Full per-iteration equality (every iteration row) is verified on the
small LP below, where the entire trace is recorded for every iteration.

`iters_since_eff_tol` behavior with repeated skips: in LAZY mode the counter
keeps incrementing while the condition is skipped and resets to 0 only when a
cond2 computation actually fires. This preserves the same cadence as CURRENT
for any iteration that ultimately recomputes, so the soft_clamp/repair gate
uses the same effective tolerance at the same decision points.

- `max_stale_iters_current/lazy`: the longest consecutive run of iterations
  without a fresh cond2 computation (i.e., the effective tolerance/kappa being
  reused). A larger LAZY value means the condition was skipped repeatedly;
  trajectories are still identical because the gates only fire on actual
  violations (min_xB < -TOL).

## Implementation

```python
# CURRENT gate (unchanged):
if iters_since_eff_tol >= RECOMPUTE_EFF_TOL:
    eff_tol, kappa = compute_effective_tol(B, b_norm)   # cond2 (exact)
    iters_since_eff_tol = 0

# LAZY gate (only control-flow change):
# skip the exact cond2 computation whenever min_xB >= -TOL;
# otherwise call the SAME compute_effective_tol and use the SAME logic.
if min_xB < -TOL and iters_since_eff_tol >= RECOMPUTE_EFF_TOL:
    eff_tol, kappa = compute_effective_tol(B, b_norm)   # identical call
    iters_since_eff_tol = 0
```

- Tolerances, pivot rules, pricing (devex), factorization (sparse LU),
  refinement, and stopping criteria are identical in both modes.
- The sparse cond1 estimator is NOT used; only the exact dense cond2.
